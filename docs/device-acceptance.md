## 手动验收（四个入口）

| 入口 | 结果 |
|---|---|
| 主屏小组件 | **通过**。`input tap` 点「睡觉」→ 尾占位条 16:32 被填成「睡觉」、17:xx 处补出新占位；`quickWrite: ok=true mode=append minutes=26`。排版正常：状态行 + 上一条 +「打开」+ 2×2 标签，无截断 |
| 快捷设置磁贴 | **通过**。磁贴显示「记一条 · 距上次记录 2 分」（副标题取自镜像，随打开面板实时算）；点开是底部选择页，四行 56dp 触控行、间距正常（这正是 `PickChip` 那条 LayoutParams 修复的验证）；点「睡觉」→ `ok=true mode=append minutes=4`，`coalesceRedundant` 把相邻同标签同文本的两段并成一段 |
| 长按图标快捷方式 | **部分**。logcat 证实注册了 5 条动态快捷方式（3 个标签 + 壳设置 + 静态「记一条」），其 intent 目标是 `QuickWriteActivity`——该宿主已由小组件路径验证；快捷方式本身的点击未在真机上点过 |
| 常驻通知的标签动作 / 直接回复 | **未通点**。通知本体、频道、`vis=SECRET`、三个动作（两标签 + 写一句）都在 `dumpsys` 里核对过，但**动作按钮的点击没能验证**：`am broadcast` 到 `exported="false"` 的接收器被系统拦下，而用 `input tap` 盲点通知栏几次都没命中（`uiautomator dump` 在通知面板展开时返回空）。缺的只是 `QuickActionReceiver` + `goAsync` 这段 plumbing，写入链路本身已由另两个入口证明 |

## 实测延迟（这是「记录阻力」那个问题的答案）

| 路径 | 数字 |
|---|---|
| 一键写入 · 热进程 | Activity `TotalTime` 59–66ms + 桥 `eval` 42–54ms ≈ **0.1 秒**（点击 → 数据落库） |
| 一键写入 · 冷进程 | Activity 244ms + 建桥 WebView 277ms + eval 275ms ≈ **0.55 秒** |
| 主界面冷启动 | `TotalTime` **545ms** |

D13 第五条「约 5 秒完成一次记录」在这条路径上是 0.1–0.55 秒。

## 三条工具教训（比缺陷本身更值钱）

1. **`adb install -g` 会盖住权限缺陷**。它一次性授予全部运行时权限，于是
   「声明了 `POST_NOTIFICATIONS` 却从不申请」这条（Android 13+ 上会让常驻通知入口
   **静默消失**）在检查里永远不会红。现在装包不带 `-g`，并主动 `pm revoke` 建立前提。
2. **`adb shell` 会在设备上重新解析整条命令行**。播种数据原本用
   `sh -c "mkdir … && echo … | base64 -d > …"`，引号在那一步散掉，重定向落到 shell
   用户上下文里静默失败，下游三条断言随之误报成「一键写不进去」。改成
   `push` + `run-as cp`，全 argv、零元字符。
3. **夹具的时刻要相对「现在」算**。第一版把尾占位点写死在 10:00，下午跑的时候空白
   已 6.5 小时——安静写入上限正确地拦下了它，而用例把「守卫在工作」判成「功能坏了」。
   夹具离现在太远，等于在测另一件事。
